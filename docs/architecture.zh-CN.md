# 架构与安全边界

源台账是权威数据。每次运行只读台账，逐行校验编号，跳过配置中的终态，再对符合条件的记录顺序查询。只有返回的 `match_code` 与请求编号完全一致时才接受结果。已取消的生命周期记录会被排除，最后一条有效提交必须且只能解析出一个白名单状态。

目标修订列必须依据台账中从 `REV-00` 开始且连续的表头计算。已完成的 `CODE-*` 状态发生变化时，必须存在下一个修订列，否则该行失败关闭。显式 `-20` 后缀属于特殊编号规则，不能当作普通的第 20 次修订。

```text
台账适配器
    │
    ▼
运行前预检 ── 失败 ──► 停止运行
    │
    ▼
编号校验 ── 编号错误 ──► 行级异常，不查询
    │
    ▼
门户适配器（逐行查询）
    │
    ▼
精确编号匹配 + 最终有效状态
    │
    ├── 结果不确定 ──► 行级异常，不生成建议
    ▼
修订规则 ── 不安全 ──► 行级异常，不生成建议
    │
    ▼
建议产物 ──► 仪表盘数据 ──► GitHub Pages
```

公开样例永不写回台账。生产写回应做成独立的私有组件，并具备明确范围、写前备份、幂等控制、审计日志和写后回读验证。
